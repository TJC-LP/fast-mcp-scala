# MCP 2026-07-28 upgrade

This change adds a native 2026-07-28 server path while preserving the
initialization-based revisions as a compatibility adapter. The two eras share
tool/resource/prompt managers and JSON-RPC framing, but they do not share
lifecycle state.

## Wire behavior

| Concern | 2026-07-28 | Compatibility adapter |
|---|---|---|
| Negotiation | `server/discover` or inline request metadata | `initialize` + `notifications/initialized` |
| Client state | Version, identity, capabilities, and log level in every request | Stored on `Session` |
| HTTP lifecycle | Independent POSTs; optional request-scoped SSE | `Mcp-Session-Id`, GET stream, DELETE |
| Additional client input | MRTR `input_required` + retry | Correlated server-initiated request |
| Subscriptions | `subscriptions/listen` POST stream | Resource subscribe/unsubscribe + GET stream |
| Tasks | `io.modelcontextprotocol/tasks` bearer handles (any transport); invisible to legacy sessions | `params.task`, list/get/result/cancel (session-scoped; rejected on the shared stateless session) |
| Results | Required `resultType`; cache hints where specified | Earlier wire shapes unchanged |
| Tool handler errors | Handler-raised `McpError` escapes as a protocol error (`-32021` → HTTP 400) | Always in-band `CallToolResult.isError` |
| Resource not found | Invalid Params (`-32602`) with `data.uri` | Reserved `-32002` with `data.uri` |
| Modern-only methods | Dispatched (`server/discover`, `subscriptions/listen`, `tasks/update`) | `-32601` Method Not Found |
| Capability gating | Per-request, incl. sub-capabilities (`elicitation.url`, `sampling.tools`/`.context`); `-32021` | Initialize-time, base capabilities only; `-32600` |

Modern HTTP requests require `Content-Type`, an `Accept` value that supports
JSON and SSE, `MCP-Protocol-Version`, and `Mcp-Method`. `Mcp-Name` is required
for tool calls, resource reads, and prompt gets. Header-backed tool arguments
are validated from `x-mcp-header` annotations, including Base64 sentinel
decoding and numeric integer comparison.

The `stateless` setting now affects only older HTTP traffic. All 2026 requests
are stateless, ignore `Mcp-Session-Id` and `Last-Event-ID`, and never mint a
session. Modern GET and DELETE requests receive 405.

## Review map

- `core/Protocol.scala`, `jsonrpc/McpError.scala`, and `core/wire/Envelopes.scala`:
  version, allocated errors, request/result shapes, cache fields, and
  subscriptions.
- `server/router/RequestContext.scala`, `McpRouter.scala`, and `McpContext.scala`:
  per-request isolation, version dispatch, result metadata, MRTR, and logging.
- `server/router/Builtins.scala`: the era seams — the tools/call error
  contract (in-band vs protocol error) and the resource-miss code split.
- `server/transport/HttpHeaderValidation.scala` and
  `server/transport/ModernHttpValidation.scala` plus the JVM/Bun backends:
  header/body validation, version classification, stateless modern routing,
  response status mapping, and response-stream cancellation.
- `server/router/TaskRouting.scala` and `server/manager/TaskManager.scala`:
  official extension handles, bearer lookup, polling, cancellation, and the
  isolated legacy task path.
- `Protocol20260728Test`, `JvmHttpTransportTest`, and `JsServerHttpTest`:
  executable protocol fixtures and cross-platform transport behavior.

## Deliberate boundaries

- Roots, Sampling, and Logging remain available because the new revision
  deprecates rather than removes them. New server code should prefer explicit
  tool/resource parameters, direct provider APIs, and stderr/OpenTelemetry.
- `subscriptions/listen` is fully lifecycle-safe and acknowledges only
  notification types the server can emit. The library does not yet expose
  dynamic list/resource-change publishers, so those filters are declined.
- The Tasks extension currently produces working/completed/failed/cancelled
  tool tasks. `tasks/update` validates the protocol shape, but the server does
  not yet suspend task execution in `input_required`. Task-status notifications
  (`notifications/tasks/status`) are emitted on legacy 2025-11-25 sessions on
  every terminal transition; modern bearer tasks do not emit them — the
  2026-07-28 extension moved status to polling (`tasks/get`).
- Authorization and client-registration changes are outside this server
  library's current surface; no OAuth authorization server or MCP client
  credential store is implemented here.

## 1.0.0-RC1 gate ledger

How each RC1 criterion was met (decisions confirmed by the maintainer,
2026-08-17, tracked as TJC-2000):

- **Official 2026-capable conformance oracle** — met via
  `@modelcontextprotocol/conformance@0.2.0-alpha.11`, the first release
  carrying the 2026-07-28 scenario set. Both platforms pass
  `scripts/conformance.sh {jvm|js} <port> 2026` (`--requirements 2026-07-28`,
  every scored scenario green; the failing scenarios are ones the harness
  itself marks `extension`/`pending` and does not score). The stable TS SDK
  (1.30.0) still declares 2025-11-25, so the alpha was accepted as the RC
  oracle; **re-validate against a stable oracle before 1.0.0 final**.
- **Harness pin** — the conformance oracle version lives in
  `conformance/package.json`; bump it and regenerate `conformance/bun.lock`
  with the Mill-managed Bun in a reviewed PR (the lock diff is the review
  surface — `--frozen-lockfile` enforces the lock, not package.json).
- **External client end-to-end** — the conformance harness's synthetic client
  drives discovery, list/call/read/get, MRTR (single, multi, multi-round,
  tampered-state), and the HTTP header-negative cases. Validation by an
  independent external client against the published RC artifact is exactly
  what the RC period is for.
- **2025-11-25 compatibility matrix** — the active suite runs every scenario
  on both protocol eras (73 checks, empty baselines, JVM + Bun), and the JS
  ConformanceTest drives the real TS SDK 1.29.0 client over stdio.
- **Soak test** — `LifecycleSoakTest`: 25 dropped `subscriptions/listen`
  streams and 10 TTL-expired running tasks leave no fibers or task entries
  behind.
- **Tasks limitations** — ship documented (maintainer decision): the extension
  stays opt-in and off by default; `tasks/update` input resumption and modern
  task-status notifications remain unimplemented and documented. The
  `tasks-*` conformance scenarios are unscored extensions.
- **Version move** — `build.mill` default moves `0.5.0-SNAPSHOT → 1.0.0-RC1`
  in this release-preparation commit; the tag `v1.0.0-RC1` publishes with the
  prerelease flag, and a post-release commit bumps the dev default.
